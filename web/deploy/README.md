# Установка сайта профайлера на VPS

Этот установщик ставит сайт профайлера Amazake (сюда `/amazake profile` отправляет отчёты, а вы
открываете их по ссылке `https://ваш-домен/r/<id>`) на VPS с Ubuntu или Debian. Он рассчитан на
сервер, где **уже работает что-то важное, например Discord-бот**, и ничего из этого не трогает.
Подробности в разделе [«Почему это не заденет бота»](#почему-это-не-заденет-бота).

Что получится:

- сайт работает отдельным сервисом `amazake-web` на `127.0.0.1:8787`, от отдельного пользователя,
  с ограничением памяти и процессора;
- снаружи его отдаёт nginx по вашему домену, с HTTPS от Let's Encrypt (бесплатно, продлевается само);
- если порты 80/443 уже заняты чем-то другим (Caddy, Apache, docker и т.п.), nginx не ставится,
  а установщик показывает, какие строки добавить в ваш веб-сервер.

## Что нужно заранее

1. **Домен или поддомен** для сайта, например `profiler.example.com`. Сайт займёт его целиком.
2. **A-запись DNS** этого домена на IP вашего VPS. Делается у регистратора домена или в Cloudflare
   (если Cloudflare, на время получения сертификата выключите «оранжевое облако», то есть proxy).
   IP сервера можно узнать командой `curl -4 ifconfig.me` или в панели хостинга.
   Если запись ещё не работает, установка всё равно пройдёт, просто без HTTPS; потом запустите её ещё раз.
3. **Почта** для Let's Encrypt (туда приходят только предупреждения об истечении сертификата).
4. Доступ к серверу по SSH и `sudo`.

## Установка

Подключитесь к VPS по SSH и выполните команды по порядку.

**1. git**, если его ещё нет. `--no-remove` не даёт apt удалять пакеты, `NEEDRESTART_*` отключают
предложение Ubuntu перезапустить службы после apt:

```bash
command -v git || sudo env NEEDRESTART_MODE=l NEEDRESTART_SUSPEND=1 apt-get install --no-install-recommends --no-remove git
```

Здесь специально нет `-y`. Если apt захочет поставить что-то кроме git, он покажет список и спросит
`Do you want to continue? [Y/n]`. Прочитайте список: если там есть строка
`The following packages will be upgraded` (будут обновлены уже установленные пакеты), ответьте `n`,
чтобы ничего не обновлять (git тогда можно поставить позже, когда будете готовы к обновлению).

**2. Скачать код:**

```bash
sudo git clone --depth 1 https://github.com/tearsmilk/amazake /opt/amazake-src
```

Если папка уже есть (вы ставили раньше), вместо этого обновите её:

```bash
sudo git -C /opt/amazake-src pull --ff-only
```

**3. Пробный запуск.** Ничего не меняет, только показывает: что сейчас работает на сервере (бот должен
быть в списке), кто занимает порты 80/443, и точный план действий. Подставьте свой домен и почту:

```bash
sudo bash /opt/amazake-src/web/deploy/install.sh --domain profiler.example.com --email you@example.com --generate-token --dry-run
```

Прочитайте вывод. Если в конце написано «Установка невозможна», там же сказано почему и что сделать.

**4. Установка** (та же команда без `--dry-run`). Установщик ещё раз покажет план и спросит `Продолжить? [y/N]`:

```bash
sudo bash /opt/amazake-src/web/deploy/install.sh --domain profiler.example.com --email you@example.com --generate-token
```

В конце будет итог: адрес сайта, команды для журнала и **токен**. Токен показывается один раз,
скопируйте его (если потеряли: `sudo cat /etc/amazake-web/tokens`). `--generate-token` создаёт
токен только при первой установке, при повторных запусках старый токен сохраняется.

Проверка: откройте `https://profiler.example.com` в браузере, должна открыться страница профайлера.

## Настройка Minecraft-сервера

В `amazake.yml` на сервере Minecraft:

```yaml
profiler:
  upload-url: "https://profiler.example.com"
  upload-token: "токен из итога установки"
```

Перезапустите сервер Minecraft (или перезагрузите конфиг) и выполните `/amazake profile`. Через
указанное время в чат придёт ссылка на отчёт.

Если вы ставили без `--generate-token` и без `--token`, сайт принимает отчёты без токена, и
`upload-token` оставьте пустым. Так делать не рекомендуется: любой, кто знает адрес, сможет
загружать отчёты и занимать место на диске VPS.

## Обновление

```bash
sudo git -C /opt/amazake-src pull --ff-only
sudo bash /opt/amazake-src/web/deploy/install.sh --domain profiler.example.com
```

Повторный запуск обновляет файлы сайта и перезапускает **только** `amazake-web`. Ничего не
дублируется; отчёты, токен и сертификат сохраняются. Почта, `--no-https`, `--no-nginx`, порт, срок
хранения и лимит запоминаются с прошлой установки (в `/etc/amazake-web/install.conf`), их не нужно
повторять. Точная команда обновления печатается в конце установки. Чтобы отменить запомненный
`--no-https` или `--no-nginx`, добавьте `--https` или `--nginx`.

## Полезные команды

| Что | Команда |
|---|---|
| Состояние сайта | `systemctl status amazake-web` |
| Журнал сайта | `journalctl -u amazake-web -f` |
| Перезапустить сайт | `sudo systemctl restart amazake-web` |
| Настройки (адрес, срок хранения, лимит) | `sudo nano /etc/amazake-web/amazake-web.env`, затем перезапуск сайта |
| Токен | `sudo cat /etc/amazake-web/tokens` |
| Где отчёты | `/var/lib/amazake-web/data/reports/` |

Параметры установщика (`install.sh --help`):

| Параметр | Что делает |
|---|---|
| `--domain ДОМЕН` | домен сайта (обязательно) |
| `--email ПОЧТА` | почта для Let's Encrypt, нужна для HTTPS |
| `--no-https` | без сертификата, только HTTP |
| `--https` | вернуть HTTPS после установки с `--no-https` |
| `--port ПОРТ` | внутренний порт сайта, по умолчанию 8787 (если он занят, установщик скажет) |
| `--no-nginx` | не трогать nginx, поставить только сервис сайта |
| `--nginx` | снова разрешить nginx после установки с `--no-nginx` |
| `--generate-token` | создать токен, если его ещё нет |
| `--token ТОКЕН` | задать свой токен (16+ символов) |
| `--remove-token` | отключить токен |
| `--retention-days N` | сколько дней хранить отчёты (30; 0 = всегда) |
| `--rate-limit N` | загрузок в час с одного IP (30; 0 = без ограничения) |
| `--source ПАПКА` | откуда брать код (по умолчанию репозиторий, где лежит скрипт) |
| `--dry-run` | только показать план |
| `--yes` | не спрашивать подтверждение |

## Удаление

```bash
sudo bash /opt/amazake-src/web/deploy/uninstall.sh --dry-run   # посмотреть план
sudo bash /opt/amazake-src/web/deploy/uninstall.sh             # удалить сайт, отчёты оставить
sudo bash /opt/amazake-src/web/deploy/uninstall.sh --remove-cert   # удалить сайт и его сертификат, отчёты оставить
sudo bash /opt/amazake-src/web/deploy/uninstall.sh --purge     # удалить и отчёты, и сертификат сайта
```

Удаляется только своё: сервис `amazake-web`, наш файл сайта в nginx (после `nginx -t` и reload),
`/opt/amazake-web`, `/etc/amazake-web`, пользователь `amazake-web` (только если его создал
установщик). Пакеты nginx и certbot, другие сайты и другие сертификаты остаются. Папку с кодом можно
удалить потом: `sudo rm -rf /opt/amazake-src`.

Без `--remove-cert` и `--purge` сертификат сайта остаётся, но продлеваться больше не сможет (его
проверочная папка удаляется вместе с сайтом), и Let's Encrypt пришлёт письма об истечении. Удалить
его можно и потом: `sudo certbot delete --cert-name profiler.example.com`.

## Если что-то не так

- **«порт 8787 уже занят другой программой».** Это может быть ваш бот. Ничего не трогайте, просто
  добавьте `--port 8788` (или другой свободный) к команде установки.
- **«Порты 80/443 заняты не системным nginx».** На сервере уже есть веб-сервер (Caddy, Apache,
  nginx в docker, панель бота и т.п.). Установщик его не трогал и вывел готовые строки для Caddy,
  Apache и nginx. Добавьте их в свой веб-сервер сами, проверьте его конфиг и сделайте reload.
- **«http://домен пока не ведёт на этот сервер», нет HTTPS.** Проверьте A-запись: `getent hosts profiler.example.com`
  должен показать IP сервера. Подождите, пока DNS обновится (до часа), и запустите установку ещё раз.
  Ещё причина: порт 80 закрыт файрволом хостинга или `ufw`. Установщик файрвол не меняет; открыть
  порты можно так: `sudo ufw allow 80,443/tcp` (только если ufw включён и вы понимаете, что делаете).
- **«nginx -t уже сейчас выдаёт ошибку».** В nginx уже есть ошибка в чужом конфиге. Установщик её
  не исправляет и ничего не меняет. Исправьте её или поставьте с `--no-nginx`.
- **«в nginx уже есть другой сайт с server_name ...».** Этот домен уже занят другим сайтом в nginx.
  Возьмите другой поддомен.
- **«наш сайт стал бы сайтом по умолчанию для ...».** В вашем nginx на этом порту есть сайты, но ни у
  одного нет `default_server`, и первым загрузился бы наш файл. Тогда запросы по IP сервера
  (например, вебхук бота вида `http://IP/...`) пошли бы к нам. Установщик ничего не поменял. В
  указанном файле допишите `default_server` к `listen` этого порта (например `listen 80 default_server;`),
  выполните `sudo nginx -t && sudo systemctl reload nginx` и запустите установку снова. Или `--no-nginx`.
- **«nginx -t не примет наш файл сайта ...» с `server_names_hash_bucket_size`.** Домен слишком длинный для
  стандартных настроек nginx. Добавьте в блок `http { ... }` файла `/etc/nginx/nginx.conf` строку
  `server_names_hash_bucket_size 128;`, проверьте `sudo nginx -t`, сделайте `sudo systemctl reload nginx`
  и запустите установку снова. Или возьмите домен короче.
- **«есть сертификаты, которые продлеваются через порт 80».** Другой сертификат на сервере (например,
  бота) продлевается через `certbot --standalone` (или через Apache/nginx, которые сейчас не запущены).
  Если поставить или запустить nginx, он займёт порт 80, и это продление сломается. Поставьте сайт с
  `--no-nginx` и подключите его к своему веб-серверу, или сами переведите тот сертификат на `--webroot`.
- **«пользователь amazake-web уже есть, но создан не этим установщиком».** На сервере уже есть чужая
  учётная запись с таким именем. Установщик её не использует и не удаляет; разберитесь с ней сами.
- **«apt хочет обновить уже установленные пакеты».** Чтобы поставить nginx или certbot, apt
  потребовал обновить что-то из уже установленного. Установщик этого не делает и остановился, ничего
  не поставив. Можно подключить сайт к уже имеющемуся веб-серверу (`--no-nginx`) или поставить
  пакеты вручную, когда будете готовы.
- **Сайт открывается, но выдаёт 502.** Сервис сайта не работает: `journalctl -u amazake-web -n 50`.
- **В Minecraft «сайт отказал в доступе (401)».** Токен в `amazake.yml` не совпадает с `sudo cat /etc/amazake-web/tokens`.
- **Установка прервалась с ошибкой.** В выводе написано, что уже сделано, а что нет. Другие сервисы
  при этом не затрагиваются. Исправьте причину и запустите ту же команду ещё раз, или удалите всё `uninstall.sh`.
- **Проверить, что бот жив:** `systemctl list-units --type=service --state=running`, `pm2 ls`
  (от пользователя, под которым запущен бот) или `docker ps`, смотря как он запущен.

## Почему это не заденет бота

- **Сначала только проверка.** Перед любыми изменениями установщик лишь смотрит (`ss -ltnp`,
  список сервисов, процессы pm2, `docker ps`) и показывает план. Сам `pm2` не вызывается, потому что он может
  запустить свой демон; процессы pm2 видны через `ps`. `docker ps` вызывается, только если демон docker
  уже работает (иначе он мог бы запустить демон, а с ним старые контейнеры, например старую копию бота).
  Наш файл nginx заранее проверяется `nginx -t` на временной копии конфигурации, `/etc/nginx` при этом
  не меняется. Без вашего «y» (или `--yes`) ничего не меняется.
- **Перезапускается только `amazake-web`.** Никаких `restart`/`stop`/`kill` других сервисов. nginx
  только перечитывает настройки (`nginx -t && systemctl reload nginx`), это не прерывает его работу.
  nginx запускается, только если его не было или он был остановлен и порты 80/443 свободны, и только
  если ни один сертификат на сервере не продлевается через порт 80 (`certbot --standalone`). В
  автозапуск nginx включается, только если установщик сам его поставил; если вы его отключали, это так и останется.
- **Чужие файлы не меняются.** Добавляется один свой файл сайта nginx `zz-amazake-web.conf` (с пометкой
  `managed by amazake-web installer`) только для вашего домена и без `default_server`. Имя на `zz-`
  нужно, чтобы он загружался после ваших сайтов: если на порту 80 или 443 у ваших сайтов нет
  `default_server`, сайтом по умолчанию остаётся ваш первый сайт, и запросы по IP или с чужими доменами
  идут туда же, куда раньше. Установщик это проверяет (`nginx -T`) до установки и ещё раз перед reload.
  Если на каком-то порту (например, 443) больше никто не слушает, наш сайт там единственный, другим
  сайтам это ничего не меняет. Если `nginx -t` или эта проверка не прошли, файл убирается, а nginx не
  перезагружается. `nginx.conf`, конфиги Caddy/Apache, `/etc/hosts`, DNS не трогаются.
- **certbot не правит nginx.** Используется `certbot certonly --webroot`: certbot только кладёт
  проверочный файл в нашу папку `/var/lib/amazake-web/acme`.
- **Никаких обновлений системы.** Нет `apt upgrade`, `full-upgrade`, `dist-upgrade`, `autoremove`.
  Ставятся только nginx и/или certbot и только если их нет, с `--no-install-recommends` и `--no-remove`.
  Если apt захочет обновить или удалить хоть один уже установленный пакет, установка останавливается. Ubuntu-шный `needrestart`
  отключён (`NEEDRESTART_MODE=l NEEDRESTART_SUSPEND=1`), поэтому после apt никакие службы не перезапускаются.
- **Системный Python не меняется.** Сайт работает на `/usr/bin/python3` и только на стандартной
  библиотеке: нет `pip install`, нет venv, нет глобальных пакетов npm/pip.
- **Не трогаются** docker, pm2, файрвол (ufw/iptables), сеть, пользователи, кроме своего `amazake-web`.
  Если пользователь или группа `amazake-web` уже есть и созданы не установщиком, установка останавливается.
- **Сайт не может отнять ресурсы у бота.** Сервис ограничен: не больше 256 МБ памяти и половины
  одного ядра процессора, низкий приоритет процессора (`Nice=10`, `CPUWeight=20`) и диска
  (`IOSchedulingClass=idle`), не больше 64 потоков. Если памяти на сервере не хватит, ядро первым
  завершит сайт, а не бота (`OOMScoreAdjust=500`).
- **Сайт изолирован.** Отдельный пользователь без входа в систему; сайт слушает только `127.0.0.1`;
  писать может только в `/var/lib/amazake-web/data`; не видит домашние папки (а значит, и файлы
  бота); без привилегий (`NoNewPrivileges`, пустой `CapabilityBoundingSet`, `ProtectSystem=strict`).
- **Порт не отбирается.** Если порт 8787 занят чем-то другим, установка останавливается и просит `--port`.
- **Удаление тоже аккуратное.** `uninstall.sh` удаляет только файлы с нашей пометкой, только
  пользователя, которого создал установщик, и только наш сертификат (и только с `--remove-cert` или `--purge`).
