# AmazakeStress

Плагин для **воспроизводимого** стресс-теста серверов Minecraft **1.21.11** на базе Paper.
Нужен, чтобы честно сравнить два сервера (например, Leaf и Amazake) на одинаковых машинах:
плагин создаёт одинаковую нагрузку, вы снимаете отчёт профайлера на каждом сервере
и сравниваете их рядом на <https://mc-ru.org>.

* Работает на любом сервере на базе Paper 1.21.11 (Paper, Leaf, Amazake и т. д.): использует только
  публичный Paper API, без NMS и рефлексии.
* **Детерминированность**: одинаковый `config.yml` даёт одинаковую нагрузку — отдельный мир
  `stress_world` с фиксированным сидом (по умолчанию `20261111`), постройки по фиксированным координатам,
  все случайные решения из `java.util.Random(seed)`, расписание этапов в тиках.
* **Безопасность**: плагин работает только в своём мире `stress_world` и не трогает остальные миры.

## Этапы нагрузки

Нагрузка нарастает: то, что включилось на этапе, работает до конца прогона.

| № | Этап | Что добавляется | По умолчанию |
|---|---|---|---|
| 0 | baseline | ничего (замер «пустого» сервера) | 20 с |
| 1 | mobs | мобы с ИИ (по умолчанию 800) | 30 с |
| 2 | physics | падающие блоки, жидкости, TNT, предметы | 30 с |
| 3 | redstone | редстоун-часы (40), цепочки воронок (64) | 30 с |
| 4 | chunks | загрузка/генерация/выгрузка чанков (кольцо радиусом 24) | 30 с |
| 5 | packets + async | пакеты (частицы, звуки, блоки, движение) и асинхронная нагрузка «как у плагина» | 30 с |
| 6 | max | всё сразу на максимуме (×1.5) до конца | остаток (130 с) |

Итого по умолчанию 300 с (6000 тиков). Все длительности и интенсивности — в `config.yml`.

## Установка

1. Скачайте `AmazakeStress-<версия>.jar` (собирается в GitHub Actions или командой
   `./gradlew -p stress-plugin build` из корня репозитория Amazake → `stress-plugin/build/libs/`).
2. Положите jar в папку `plugins/` **на оба сервера**.
3. Запустите сервер. Появится `plugins/AmazakeStress/config.yml` — если меняете его,
   скопируйте **один и тот же** файл на оба сервера.

Права: `stress.admin` (по умолчанию у операторов).

## Команды

| Команда | Что делает |
|---|---|
| `/stress start [all\|mobs\|physics\|redstone\|chunks\|packets\|async] [секунды]` | запустить все этапы (`all`, по умолчанию) или один модуль; время 10–7200 с |
| `/stress run [all\|модуль] [секунды]` | то же, что `start`, плюс встроенный профайлер ровно на время прогона: в конце отчёт отправляется на сайт (`profiler.upload-url`) и в чат приходит ссылка |
| `/stress stop` | остановить, убрать всех созданных сущностей, остановить все задачи, снять тикеты чанков |
| `/stress status` | текущий этап, счётчики модулей, TPS/MSPT прямо сейчас |
| `/stress profile [секунды\|stop]` | встроенный профайлер (по умолчанию 300 с) |
| `/stress cleanup confirm` | выгрузить и удалить мир `stress_world` |

После прогона в консоль и в `plugins/AmazakeStress/results/run-<дата>-<режим>.txt` пишется сводка:
по каждому этапу — реальный TPS, средний MSPT, p95/p99, максимум и число тиков дольше 50 мс,
плюс версия сервера, Java и JVM-флаги.

## Порядок честного сравнения

1. **Одинаковые машины**: две одинаковые 3-ядерные машины (тот же тип VPS/железа, та же ОС),
   ничего лишнего не запущено.
2. **Одинаковая Java и одинаковые JVM-флаги** (тот же `-Xms/-Xmx`, тот же GC и набор флагов) в скриптах запуска.
3. **Одинаковые настройки сервера**: `server.properties` (`view-distance`, `simulation-distance`,
   `online-mode`, `max-players`), а также общие для Paper файлы конфигурации — по возможности с одинаковыми
   значениями. Собственные оптимизации форка оставьте как есть: именно их и сравниваем.
4. **Одинаковый `plugins/AmazakeStress/config.yml`** (тот же сид, этапы и интенсивность).
   Других плагинов — нет (или одинаковый набор).
5. **Свежий сервер**: перезапустите сервер перед замером. Мир `stress_world` пересоздаётся
   автоматически перед каждым прогоном (`world.recreate-on-start: true`).
6. **Прогрев**: после старта подождите 2–3 минуты, чтобы JIT прогрелся и сервер успокоился.
   Можно сделать пробный короткий прогон (`/stress start all 60`), он не повлияет на следующий —
   мир будет пересоздан.
7. **Никто не заходит на сервер** во время замера (игроки — это дополнительная, разная нагрузка).
8. **Запуск** — одновременно в консоли каждого сервера:
   ```
   /stress run 300
   ```
   `run` запускает все этапы и профайлер с первого до последнего тика прогона (то же самое делает
   `/stress start all 300` при `profiler.auto-start-with-run: true`).
9. Дождитесь сообщения «Прогон завершён» и ссылки «Отчёт готов: …» от профайлера.
10. Откройте обе ссылки на <https://mc-ru.org> и сравните отчёты рядом (если отправка не удалась, отчёт лежит в
    `plugins/AmazakeStress/profiles/` — его можно перетащить на страницу сайта). Для повторяемости сделайте
    2–3 прогона на каждом сервере и сравнивайте медианные результаты.

Расписание считается в **тиках**: на сервере, который тормозит, прогон длится дольше по реальному времени,
но нагрузка в каждом тике одинаковая. Сводка в `results/` показывает реальный TPS и MSPT на каждом этапе.

## Безопасность

* Плагин создаёт, меняет и удаляет **только** мир `stress_world`. Все постройки, мобы и тикеты чанков —
  только там.
* Мир помечается файлом `amazake-stress.marker`. Если папка `stress_world` есть, но создана не плагином,
  плагин откажется с ней работать.
* `/stress stop` останавливает все задачи плагина, удаляет всех созданных сущностей и снимает тикеты чанков.
  Постройки остаются до следующего запуска (мир пересоздаётся) или до `/stress cleanup confirm`.
* `/stress cleanup confirm` переносит игроков из `stress_world` на спавн основного мира, выгружает мир
  без сохранения и удаляет его папку. Без слова `confirm` ничего не удаляется.
* Модуль `packets` при `teleport-players: true` один раз за прогон переносит онлайн-игроков на свою площадку в
  `stress_world`; при остановке прогона они возвращаются туда, где стояли.
* При выключении плагина/сервера прогон останавливается автоматически.
* **Не запускайте на рабочем сервере с игроками**: плагин специально доводит сервер до предела.
